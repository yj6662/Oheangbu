## 1. Authority

- SPELL-BRUSH(필세 정의 — 형×세) · ART-INK(갈필=순수 비주얼 · 발광 상한) · **ART-UI(먹 미터 LOCKED — "먹 부족 시 획이 갈필로 그어짐"=보조 언어)** · PROD-TOOLS(Ribbon Mesh + Noise Cutout) · CLAUDE.md 인식 불가침 · SPEC-MIG-BRUSH-STROKE(기초 Geometry 계층)

## 2. Goal

> **획이 「붓으로 그은 것」으로 보이게 하는 형태 언어를 확립한다.**

SPEC-MIG-BRUSH-STROKE가 확보한 것은 균일한 폭의 리본 메시다. 지금은 모든 점의 폭이 상수이고
농도는 항상 1.0이라, 붓이 아니라 테이프에 가깝다. 이 Spec은 **Geometry 층에서 할 수 있는 것**을 끝낸다:
폭의 변화 · 기필/수필 · UV 규약 · 먹 농도 채널.

**셰이더는 다루지 않는다** — 갈필·번짐·한지 질감은 다음 Spec(SPEC-SPIKE-INK-LOOKDEV)이다.
이 순서를 지키는 이유: 획이 이상해 보일 때 Geometry 문제인지 Shader 문제인지 구별하려면
맨 메시가 먼저 납득돼야 한다(SPEC-MIG-BRUSH-STROKE §15 합의).

## 3. 대상 — 형태 언어 4축

| # | 축 | 내용 | 근거 |
|---|---|---|---|
| 1 | **폭(width)** | 속도 기반 변조(빠르면 가늘게·느리면 굵게) + 유기적 노이즈 | 붓의 물리 — 빠른 획은 붓털이 덜 눌린다 |
| 2 | **기필(起筆)** | 획 시작 몇 샘플의 눌림(폭 증가) | 붓을 종이에 대는 순간의 압력. 현재 미구현 |
| 3 | **수필(收筆)** | 획 끝을 빼는 taper | 이미 구현됨 — 이 Spec에서 수치 확정 |
| 4 | **먹 농도(ink)** | 정점 알파 채널. **먹 잔량**(주) + 속도(부)에 따른 감쇠 | ART-UI LOCKED: 먹 부족 시 갈필 = 먹 미터의 보조 언어 |

- 1·2·4는 **표현 계층에서 계산**한다(어댑터 또는 렌더러). Raw 입력에는 손대지 않는다.
- 속도는 표현용으로 **다시 측정**한다 — 인식용 `StrokePoint.Time`을 읽어 쓰지 않는다(인식 불가침의 데이터 방향 유지).

## 4. UV 규약 확정

현재 `RibbonMeshBuilder`는 U=획 진행률(0→1), V=폭 방향(0→1)을 쓴다. 이 Spec에서 **계약으로 확정**한다:

- **U = 획 진행률** — 기필·수필이 획 양끝에 얹히고, 붓결 텍스처가 획을 따라 흐른다.
- **V = 폭 방향** — 중앙(0.5)이 진하고 가장자리가 먼저 갈라지는 갈필 표현의 좌표.
- **정점 알파 = 먹 농도** — 셰이더가 읽을 채널.

다음 Spec(LOOKDEV)이 이 규약 위에 Noise Cutout을 얹으므로, **여기서 확정하면 셰이더 작업 중
Geometry를 다시 건드리지 않아도 된다.**

| 실시간 먹 **소모**(`_drawInkPerMeter`) | **제외** — 먹을 깎는 것은 Combat 소유. 이 Spec은 **읽기 전용** (§5.2) |
| 소멸 연출·글로우(`_glowColor`) | **제외** — 약발동 개념 소멸 + 발광 상한 저촉 소지 |

### 5.2 먹 잔량 연동의 경계 [결정 2026-08-26]

ART-UI가 **"먹 부족 시 획이 갈필로 그어짐"을 이미 LOCKED**로 두고 있다(먹 미터의 보조 언어).
따라서 먹 잔량 → 획 마름은 정본 정합이며, v0.1에서 이를 "Combat 소유"로 제외한 것은 과했다 — 정정한다.

지켜야 할 경계는 **방향**이다:

```
먹 잔량 ──읽기──> 표현(농도)      허용 · 이 Spec
먹 잔량 <──쓰기── 표현            금지 · Combat 소유
농도 ──────────> 위력             금지 · 갈필=순수 비주얼(ART-INK)
```

- 렌더러는 먹을 **읽기만** 한다. 소모·차감은 하지 않는다(레거시 `_drawInkPerMeter` 제외 유지).
- **선행 조건: 먹 풀이 아직 미구현이다.** 이 Spec에서 먹 시스템을 만들지 않는다.
  대신 `float 0~1` 잔량을 받는 **읽기 전용 인터페이스**(또는 Float 이벤트 채널)만 정의하고,
  스파이크 단계에서는 하네스의 슬라이더로 잔량을 흉내 내 마름 곡선을 튜닝한다.
  실제 먹 풀이 생기면 그 값을 꽂기만 하면 되도록 접점을 얇게 유지한다.
- 감쇠 곡선은 레거시 방식을 참고한다: **임계 이상은 항상 진하게, 그 아래부터 급격히 연해짐**
  (`_paleThreshold`·`_dryDensityFloor` 계열). 선형 감쇠는 "거의 항상 조금 흐린" 상태를 만들어 가독을 해친다.

### 11.1 관성 결정을 위한 판단 재료 [육안 확인 시 확인할 것]

붓끝 관성은 표현을 입력보다 늦게 따라가게 한다 — 즉 **화면의 획과 인식된 획이 미세하게 다르다.**
존폐를 가를 질문은 두 가지다:

1. **가독**: 관성이 있는 상태에서 자기가 그린 글자를 읽을 수 있는가(ART-CHARTER 최소 요건).
2. **오인 유발**: 관성 때문에 "제대로 그린 것 같은데 다르게 인식됐다"는 억울함이 생기는가.
   특히 빠른 획·급격한 방향 전환에서 표현이 뒤처지면 이 문제가 커진다.

관성 강도를 SO 수치로 두어 **0(끔)부터 레거시 값(8)까지 연속으로 비교**할 수 있게 한다.
2번이 관찰되면 인식 불가침의 정신에 반하므로 폐기, 아니면 연출로 수용한다.

### 12.2 형태 언어 4축 — 구현 방식

- **속도**: 표현용으로 **다시 측정**한다(입력 좌표 이동량 ÷ 실시간). 인식의 `StrokePoint.Time`을 읽지 않는다 — 방향을 입력→표현으로 고정해 표현 사정이 인식에 새어 들지 않게 했다.
- **폭** = 기본 × 속도 배율(빠르면 가늘게) × Perlin 노이즈 × 기필 눌림. 노이즈는 위치가 아니라 **그은 거리**로 훑어, 같은 자리를 맴돌아도 결이 흐른다.
- **기필**: 시작 N샘플이 눌린 폭에서 평상 폭으로 풀린다(신규 — 기존엔 없었다).
- **농도** = 속도 배율 × **먹 잔량 곡선**. 잔량은 임계 이상 평평하다가 그 아래에서 하한까지 떨어진다(선형 감쇠의 "항상 조금 흐림" 회피).

### 12.3 관성 — 기본 꺼짐으로 구현

`BrushLerpSpeed = 0`(기본)이면 표현이 입력과 **정확히 일치**한다. 0보다 크면 붓끝이 지수 보간으로 따라온다(레거시 값 8).
§11.1의 판단 재료를 얻으려면 이 값을 0 → 4 → 8로 올려가며 비교하면 된다.

2. **속도 대비** — 빠르게 그은 획과 느리게 그은 획의 굵기·농도가 눈에 띄게 다른가.
3. **기필·수필** — 획 시작이 눌려 있고 끝이 빠지는가.
4. **먹 마름** — `[`를 눌러 잔량을 0 근처로 낮추고 그어 본다. 획이 마르되 **글자를 읽을 수 있는가**(ART-CHARTER 최소 요건). 못 읽으면 `_dryDensityFloor`를 올려야 한다.
5. **관성(§11.1)** — `BrushStyle_Default`의 `BrushLerpSpeed`를 0 → 4 → 8로 바꾸며 비교:
   - 자기가 그린 글자를 읽을 수 있는가
   - **"제대로 그렸는데 다르게 인식됐다"는 억울함이 생기는가** — 특히 빠른 획·급격한 방향 전환에서
   - 후자가 관찰되면 폐기(0 고정), 아니면 연출로 수용
6. **인식 회귀** — 어댑터 컴포넌트를 꺼도 인식 결과가 같은지 확인.
7. **Profiler GC** — 획을 긋는 동안 GC Alloc 관찰(SPEC-MIG-BRUSH-STROKE 잔여 조건 동반 해소).

수치가 마음에 들지 않으면 **`BrushStyle_Default.asset`을 인스펙터에서 직접 만지면 된다** — 코드 수정 불필요.

## 14. 서예 기준 → 형태 언어 매핑 (2026-08-26 · 1차 육안 피드백 반영)

1차 육안 결과(예준): ① 양끝이 스파이크로 날카로움 ② 겹침 부위 진해짐 ③ "그린 대로"에 더해
"잘 그렸다"고 느낄 보정 필요. 지시에 따라 서예의 미적 판정 기준을 조사해 기하로 번역했다.

### 14.1 조사 요지 (용필·운필 문법)

| 서예 개념 | 내용 |
|---|---|
| **장봉(藏鋒)·역입(逆入)** | 기필에서 붓끝을 획 안에 감춘다 — 역방향으로 대었다 나아가므로 시작이 **둥글고 묵직** |
| **회봉(回鋒)** | 수필에서 붓을 그어 온 쪽으로 되돌려 거둔다 — 끝이 **둥글게 맺힘** |
| **노봉(露鋒)** | 붓끝이 드러나는 뾰족한 처리 — 삐침 등 특정 획 전용이지 기본값이 아니다 |
| **필력·필압** | 굵기 변화는 「의도된 흐름」이어야 한다 — 잔떨림·울퉁불퉁함은 필력 부족의 표징 |
| **결구·장법** | 글자 짜임·전체 구성 — 개별 획 렌더링 밖. 플레이어의 몫(=필세의 형) |

1차 스크린샷 진단: 스파이크 양끝=노봉만 있고 장봉·회봉 부재 / 뼈마디 질감=노이즈 과다(0.22@25)의
필력 부족 획질 / 손떨림 그대로 노출=보정 부재. **세 문제가 전부 위 문법의 부재로 설명된다.**

### 14.2 구현 (전부 표현 전용 — 인식 Raw 무접촉)

| 서예 기준 | 구현 | 위치 |
|---|---|---|
| 장봉(둥근 기필) | 획 시작에 반원 캡(부채꼴 지오메트리) | `RibbonMeshBuilder.AddCap` |
| 회봉(둥근 수필) | taper가 폭을 0이 아닌 **잔여 폭**(TipWidth 0.35)까지만 줄이고, 끝 반원 캡이 감쌈. TipWidth→0이면 노봉 | 렌더러 EndStroke + 캡 |
| 수필 곡선 | 선형(스파이크) → SmoothStep(붓이 빠지는 곡선) | 렌더러 EndStroke |
| 필력(잔떨림 제거) | Chaikin 위치 평활(패스 0~3, 기본 2) — 끝점 보존, 꺾임(折)은 패스가 적을수록 삶 | 빌더 |
| 획질(굵기 흐름) | 폭 1-2-1 저역 통과(패스 0~4, 기본 2) + 노이즈 대폭 완화(0.22→0.08, freq 25→6) | 빌더 + SO |

- **보정의 한계선**: 평활은 손떨림을 지우지 형태를 바꾸지 않는다(끝점 보존·저패스). 「잘 그렸다」는
  느낌은 주되, 못 그린 글자를 잘 그린 것으로 둔갑시키지 않는다 — 필세의 형 판정은 Raw가 하므로
  위력·인식 어느 쪽도 속일 수 없다.

### 14.3 겹침 진해짐 (피드백 ②)

- 먹색을 근흑(#141210 계열)으로 낮춤 — 어두울수록 알파 중첩의 명도 차가 눈에 안 띈다(예준 제안 그대로).

  **근본 해결은 LOOKDEV 셰이더의 블렌딩 설계**(중첩 불변 블렌드·스텐실 등)로 넘긴다. 마른 획(알파<1)에서는
  여전히 미세하게 보일 수 있음을 기록해 둔다.
