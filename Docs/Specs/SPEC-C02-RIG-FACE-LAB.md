## 기준 자료와 단계 A — 몸·의복

1. 실제 최신 모델·클립·텍스처와 Baseline/Repair2의 대응을 확인한다. 파일 이름만으로 최신성을 판단하지 않는다. 불명확하면 선택한 실제 모델의 기준 영상을 다시 만든다. 메시·UV·재질·사용 텍스처·정지 행렬·웨이트·원본 클립 범위/FPS를 남긴다.
2. A에서는 클립의 시간·동작 범위를 바꾸지 않는다. rest 메시, 기존 리그+원본 동작, 수정 웨이트/국부 메시, 이후 보조 변형을 구분한다. 겨드랑이·어깨 → 소매·팔꿈치 → 다리에 끌리는 자락 순으로 원인을 찾는다.
3. 실제 경고 위치·위상·의복 층·좌우를 확인해 제한적으로 수정한다. 반대 다리/다른 옷 층에 무차별 최근접 웨이트 전사, 전신 Shrinkwrap·용접, 전부 골반 고정, 동작 축소·프레임 삭제·카메라 은폐로 결함을 감추지 않는다. 가능한 한 기존 본 이름·정지 자세·계층을 유지한다.
4. 동일 원본 Idle·Walk·Run·Attack, 팔 내리기·깊은 팔꿈치 굽힘·머리 위 팔·몸통 비틀기·양발 접지 스쿼트를 검사한다. 부족한 진단만 별도로 만들고 원본을 보존한다. 수치는 모든 정수 프레임, 연속 영상은 최악 구간과 대표 동작을 확인한다.
5. 같은 카메라·조명·재질에서 전후를 비교하며 중립 회색과 실제 재질을 모두 확인한다. 에지 배율은 위치를 찾는 경고이며 자동 합격/탈락 판정이 아니다. 통합 메시에서 신뢰할 수 없는 관통값은 `UNVERIFIED`; 0이나 부호 없는 최근접 거리로 통과를 선언하지 않는다.

## 단계 B — 동작·보조 움직임

가장 잘 검증된 A 체크포인트를 보존한 뒤 원본 클립의 사본에서 무게중심·팔 흔들림·발 접지·루프·전환을 조정한다. 원래 리그 개선과 동작 편집의 효과를 따로 비교한다. 지면을 두고 in-place/root motion 및 실제 이동 속도를 구분한다.

안정된 영역부터 적은 수의 보조 본·shape key를 사용한다. FitRigV3의 Cloth 프록시→다수 본 근사 베이크 경로는 도입하지 않는다. 클립에 구운 변형과 Unity 실시간 보조 움직임을 구분하며 런타임 제어기가 없으면 실시간 물리로 보고하지 않는다. 실시간 기능은 정지·회전·클립 변경·시간 간격·초기화 시 누적 변형과 발산을 검사한다.

원래 속도의 **Run 6회 이상 반복**, 시작·정지, `Idle → Run → Idle → Attack`을 검수한다. 손가락 개폐와 기존 붓의 실제 접촉은 별도 기록한다. 본·소켓만 존재하는 상태는 손 파지 완료가 아니다.

## 단계 C — 기본 얼굴 기능

몸·의복 체크포인트와 분리된 얼굴 실험 사본에서 눈알·눈꺼풀 틈·입술 연결·턱·입안·수염·눈썹·머리 연결이 실제 기하인지 텍스처인지 먼저 진단한다. 정면·양측면·3/4 근접과 실제 메시 위 랜드마크를 확인하며 bounding box만으로 즉시 얼굴을 변형하지 않는다.

1. 양쪽 눈깜박임: 중립 → 반쯤 → 닫힘 → 중립. 눈알 노출·눈꺼풀 붕괴·얼굴 전체 변형을 검사한다.
2. 시선: 실제 움직이는 눈알이 있을 때만 검증한다. 없으면 별도 국부 재구성으로 분기하며 그림에 그려진 눈의 이동을 시선 기능으로 취급하지 않는다.
3. 턱·작은 입 움직임: 실제 입술/턱 구조에 맞춘다. 턱 본과 key의 중복 적용, 입안 없는 큰 벌림은 허용하지 않는다.

필요한 국부 눈알·눈꺼풀·입술·단순 입안 추가는 가능하다. 연결된 입술을 벌리는 작업은 실제 위상 재구성이며 정점 이동만으로 입 구멍이 생겼다고 기록하지 않는다. 얼굴 정체성을 바꾸지 않는다. 구조 완성 뒤 최종 key용 정점 수·순서·위상을 고정한다.

A가 한도에 도달해 미해결이어도 얼굴 독립 실험은 계속할 수 있다. 다만 통합 캐릭터 PASS는 금지한다. 구현 불가능한 기능은 `FAIL`과 `BLOCKED_TOPOLOGY` 등 원인을 기록하고 나머지 검증된 기능을 보존한다. **첫 유효 얼굴 기능에서 작은 FBX 왕복과 가능하면 Unity 시험을 수행한 뒤 확장**한다. Unity 연결 실패는 Unity만 `UNVERIFIED`이며 가능한 Blender 작업을 중단할 이유가 아니다.

## 단계 D — 표정·통합

통과한 기본 기능만 사용해 눈썹 찌푸림/올림·눈 좁힘·작은 미소·입술 긴장을 가능한 범위에서 만든다. 실제 채널 이름·좌우 분리·중복을 기록한다. 프리셋은 **최대 4개: 집중·경계·미세한 웃음·통증**이며 부분 구현도 명시한다. ARKit 52종과 립싱크는 만들지 않는다.

각 채널의 **0/25/50/75/100% 및 중립 복귀**, 찌푸림+깜박임·시선+깜박임·턱+입술 조합을 정면·측면·3/4에서 검사한다. 최대값 실패를 숨기려고 검사 범위를 줄이지 않는다. 얼굴 정체성, 눈꺼풀/입술 접촉, 수염·눈썹 추종, 목 경계, 재질·노멀과 0값 기준 복귀를 확인한다. Idle·Run·Attack 위에 깜박임·표정을 함께 적용해 이중 변형이나 Animator/제어기의 동일 채널 덮어쓰기를 검사한다.

## 내보내기·Unity와 판정

- Blender 제어 본·제약·driver와 실제 내보내는 데이터는 구분한다. 필요한 본/key 동작은 내보낼 수 있게 굽거나 실제 런타임 제어기를 제공한다. Blender 모양만으로 Unity 통과를 선언하지 않는다.
- 빈 Blender에 FBX를 다시 불러 단위·축·리그·스킨·얼굴 key·조합을 검사한다. 정점 대응이 바뀌면 대응 방법이나 비교 한계를 명시한다.
- 별도 Unity 프리팹·검수 씬에서 실제 Humanoid·해당 골격의 Avatar·원본 클립·보조 본·BlendShape 이름과 범위를 확인한다. **Blender 0–1 → Unity 0–100** 변환을 명시한다. 초기 검사에서 필요한 데이터를 없애는 최적화/압축을 피하며 최종 설정은 따로 확인한다.
- Body Animator와 얼굴 제어기를 동시 시험하고 독립 검수 UI에서 채널·중립 복귀를 확인한다. 기존 게임 UI·PlayerRig·C2를 수정하지 않는다. 실제 게임 카메라 설정/거리와 외부 전신·얼굴 근접 검수 카메라를 구분한다.
- 실제 삼각형·변형 본·BlendShape·재질·렌더러 수를 보고한다. PC 성능은 측정 조건과 함께 실측해야 하며 통계만으로 성능 PASS를 선언하지 않는다. Blender 렌더를 Unity 플레이 캡처로 부르지 않는다.

## 기록·전달

단계별 최선의 검증 결과를 보존하며 최신 저장 파일을 자동으로 최선으로 고르지 않는다. 가설·변경 영역/방법·결과·회귀·채택/되돌림·시도 횟수·모델/클립/텍스처 출처, 재실행 가능한 멱등 도구를 남긴다. 작은 변경은 관련 검사, 체크포인트는 몸과 이미 통과한 얼굴 기능의 회귀를 수행한다.
