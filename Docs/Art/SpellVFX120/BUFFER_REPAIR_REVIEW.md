# Ribbon 버퍼 복구 후 실제 화면 검수

**산·상·엄의 후속 형상과 온·옷·옹의 보조 표현이 실제로 나타났다. 공통 비가시 결함은 해소됐고, 온·옷·옹도 파도 크기만 다른 상태에서 벗어났다. 이번 판정은 정지 화면의 VFX TEST이며 최종 게임 동작 통과를 뜻하지 않는다.**

## 자료와 확인 범위

- `BufferRepairedStills` 17종 85장 중 지정된 **산·상·엄·온·옷·옹·우 7종의 p0~p4, 35장**을 실제 열람했다. `ReadabilityStills`의 같은 35장과 전후 시트로 비교하고, 복구본 p2 7장은 1280×720 원본도 별도로 열었다. 나머지 10종 50장은 이 보고서의 검수 범위가 아니다.
- 원본은 16:9이며 수정하지 않았다. [7개 비교 시트와 70개 원본의 해시 목록](../../../Art/SpellVFX120/BufferRepairReview/sources.json)을 남겼다. 시트는 원본 전체를 축소해 배열했고 설명은 이미지 영역 밖에 있다.
- 최신 7종의 Runtime MVID는 모두 `342487b4-3642-4071-b5aa-d8d32f60a6d7`, 촬영은 `2026-09-09T03:35:45Z~03:35:50Z`다. 모두 `demonstrationCues=true`, `gameplayConnectionVerified=false`다.
- [실제 Unity 버퍼 복구 기록](../../../Art/SpellVFX120/MeshBufferRepair_20260909_033251156/repair.txt)은 카탈로그 메시 20개 중 Ribbon 한 개만 `vertexBuffers=0→1`이었음을 기록한다. 이전 CPU 배열·정점색·바운드 검사가 정상이었다는 사실을 실제 렌더 성공으로 취급할 수 없었던 사례다. 아래 평가는 코드 변경 설명 대신 복구 후 그림을 기준으로 했다.

## 남은 큰 확인 사항

1. **엄의 그릇 형태:** p2·p3에 보이는 것은 복구된 측벽 조각이며, 연속된 그릇 외피는 아니다. 단순히 더 키울 문제는 아니다. 물이 담기는 오목한 용기라는 인상이 필요한 최종 단계에서만 형태를 정리한다.
2. **옷의 젖음·옹의 하향 흐름:** 보조 형상은 구별되지만 정지 그림만으로는 각각 증기·구속선으로도 읽힌다. 현재 동작의 짧은 영상에서 흘러내리는 방향을 먼저 판정하고, 그 결과 없이 크기·개수 조정을 반복하지 않는다.
3. **상의 요격 맥락:** 서리 조각 표시의 복구와 실제 요격 성공은 별개다. 적 투사체 대용물이 접촉 후 변하는 검수 영상 또는 실제 신호 연동 검사가 필요하다.

이번 35장에서는 기존의 ‘리본이 아예 렌더되지 않음’에 해당하는 실패가 남지 않았다. 생산용 미술 완성, 120종 전체 재검수, 연속 모션, 실제 캐릭터 소켓, C2 배경 대비, 게임 규칙·성능은 이번 검사만으로 통과 처리하지 않는다. 검수 중 모션·메시·셰이더 소스와 Unity 상태를 변경하지 않았다.
