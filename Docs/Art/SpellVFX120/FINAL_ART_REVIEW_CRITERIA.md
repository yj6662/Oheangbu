# 술식 120 — 최종 미술 검수 기준

기준: [SPEC-SPELL-VFX120](../../Specs/SPEC-SPELL-VFX120.md), [Art & Audio Bible 1·2·3·5장](../../오행부_ArtAudio_Bible_v0_1.md), 현재 `build_manifest.json` 및 Profile/Effect/Variant/Summon/CueMotion 소스. 이 문서는 **실제 최종 렌더를 보기 전의 확인 목록**이며 PASS 보고서가 아니다. 게임 규칙과 코드는 변경하지 않았다.

## 판정 단위

- 120칸 중 배정 100개, 의도적 공백 20개, 기존 게임 연결 대상 15개를 구분한다. 공백의 시각 후보를 완성된 공격으로 계산하지 않는다.
- **실루엣·재질**, **단계와 운동**, **동사의 상황 표현**, **실전 연결**을 별도로 PASS / FAIL / UNVERIFIED로 기록한다. 시각 자산 TEST 수용이 동사·실전 연결 전체 PASS를 뜻하지 않는다.
- 로드된 DLL·재질·프로필이 촬영에 반영됐는지 먼저 확인한다. 오래된 DLL의 캡처로 최신 코드의 성공·실패를 판정하지 않는다.
- p0~4로 생성·유지·도달·소멸의 표본을 보고, 운동은 영상으로 확인한다. 짧은 효과가 수명 후반에 안 보이는 것은 정상일 수 있다. 의도된 활성 구간에도 안 보이는 경우를 비가시 결함으로 판정한다.
- `RecipeJson`의 설명과 선언된 파츠 수는 실행 증거가 아니다. 실제 실행은 profile 수치와 motion 분기, 입력 이벤트, 사용 메시·재질에 따른다. 설명에만 존재하는 절삭·정화·회수·요격을 렌더에서 봤다고 기록하지 않는다.

## 최소 미술 계약

| 항목 | 통과 조건 | 큰 실패 |
|---|---|---|
| 글자의 동사 | 형상의 배치와 시간 순서에서 붙임/전이/잔존/왕복/쳐올림/받아침 등이 구별된다. 공통 규칙의 같은 물체를 공유할 수 있으나 다른 동사를 크기·색·수명 차이만으로 대신하지 않는다. | 서로 다른 동사인데 같은 회전 링·직선 탄·파도를 그대로 보여준다. |
| 오행 차이 | 목은 생장·굽힘, 화는 상승·소진, 토는 무게·쌓임, 금은 단단한 절삭면·광택, 수는 젖은 외피·낮은 흐름이 읽힌다. | 주형상이 동일하고 보조 파편도 너무 작아 색 이외의 차이가 보이지 않는다. |
| 한국적 조형 | 검토한 구름·연화·회문·매듭·민화 형태를 알맞은 크기와 맥락에서 쓴다. 모든 효과에 큰 문양 원판을 붙일 필요는 없다. | 흰 사각형, 무작위 문자/종교 도상, 기존 완제품 VFX의 통째 복사로 정체성을 대신한다. |
| 색·재질 | 저채도 세계 위에서 안료색·먹 농담·은백 광택·비색·구리 등 허용된 차이가 보인다. 색 확장은 허용하되 지속 네온과 화면 백색 포화는 피한다. | 모든 재질이 단색 불투명 판이거나, 물/김이 단단한 조각으로 먼저 읽힌다. |
| 위치·가독 | 자기 강화는 시전자, 부착물은 대상 표면, 지면 효과는 지면, 무장은 손 주변에 놓인다. 주형상이 더미 뒤에 완전히 가려지지 않는다. | 얼굴 높이의 지면 오라, 발바닥을 가로지르는 검, 보이지 않는 충전 표시, 지속적인 지면 관통. |
| 동작 검증 | 이벤트 전에는 부착/대기, 이벤트 뒤에는 해체/전이 등 차이가 보인다. 검수용 예시 이벤트는 그렇게 표기한다. | 실제로 없던 명중·회복·요격·통로 개방을 단순 타이머 애니메이션만 보고 완료로 주장한다. |

## 우선 비교할 대상

아래는 **소스상 유사도 위험 또는 상황 시연이 필요한 목록**이다. 공유 family만으로 실패를 확정하지 않는다. 현재 100개에는 family/behavior/layout이 같은 군이 11개 있으며, 그 안에 33개 배정 효과가 들어 있다. 개별 motion이 있는 항목도 있으므로 실제 영상의 차이를 확인한다.

|---|---|---|
| 1 | 오·온·옷·옹 / 옥 | 같은 WaveCrest+Ribbon/Wave가 사용된다. 옥은 별도 왕복 분기가 있다. 나머지는 정화되는 경로, 대상에 내려오는 냉각선, 아래로 가라앉히는 흐름이 실제로 있는지 본다. 높은 파도 하나와 수치 변화만 보이면 동사 차별화 미완료다. |

## 최종 검수 기록 방식

각 잔여 문제는 `글자 / 파일·시각 / 실제로 보이는 문제 / 필요한 한 가지 수정 / 판정 범위`로 남긴다. 별도 동사가 없는 동계열 공통 규칙에는 억지 차이를 만들지 않는다. 반대로 명칭·recipe가 다르다는 이유만으로 같은 화면을 서로 다른 완성 연출로 계산하지 않는다. 밝고 어두운 배경·전투 배경, 영상, 비용·잔존 객체 검사를 실행하지 않았다면 해당 칸은 미검증으로 남긴다.
