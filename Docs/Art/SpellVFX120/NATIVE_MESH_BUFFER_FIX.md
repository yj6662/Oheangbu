# 리본 메시 버퍼 복구 — 2026-09-09

상태: **공통 비가시 결함 해소 / 전수 최종 미술 승인은 별도**.

산·상·엄·온·옷·옹의 리본은 실제 Renderer가 활성이고 알파가 1인데도 보이지 않았다. 단순 Unlit 재질에서도 동일했다. 같은 Transform에 Cube를 연결하면 보였고, 기존 리본의 CPU 정점·삼각형 배열로 새 Mesh를 구성하자 원래 재질로도 보였다.

## 확인한 원인과 수정

- 문제가 있던 Ribbon은 읽을 수 있는 46정점·44삼각형을 가지고 있었으나 `vertexBufferCount=0`이었다. 색·노멀·인덱스·서브메시 범위는 유효했다.
- 동일 Unity 6000.3.9f1 세션의 독립 재현에서 생성 메시 버퍼는 1, `EditorUtility.CopySerialized`로 복사한 메시 버퍼는 0, Mesh setter로 복사한 메시 버퍼는 1이었다. 원본 임시 메시를 파괴한 뒤에도 각각 0/1이었다. [재현 결과](../../../Art/SpellVFX120/native_mesh_copy_probe.txt).
- 카탈로그 재생성 코드를 native Mesh setter와 `UploadMeshData(false)` 방식으로 변경했다. 기존 자산 GUID와 형상·재질 연결을 유지했다.
- 현재 카탈로그의 공유 메시 20개를 조사하여 버퍼가 없는 Ribbon 1개만 복구했다. 46정점·44삼각형을 유지했다. 수정 전 원본과 결과는 [복구 기록](../../../Art/SpellVFX120/MeshBufferRepair_20260909_033251156/repair.txt)에 보존했다.

## 실제 렌더 검증

- [교차 렌더](../../../Art/SpellVFX120/RibbonCross_20260909_033004604/): 원본/Unlit 리본 비가시 → 동일 위치의 Cube 표시 → CPU 배열로 재구성한 리본 표시를 같은 카메라로 비교했다. 진단 색상은 임시 인스턴스에만 사용했다.
- [복구 후 재촬영](../../../Art/SpellVFX120/BufferRepairedStills/): 17종×5장=85장. MVID `342487b4-3642-4071-b5aa-d8d32f60a6d7`, DLL 2026-09-09 03:34:45 UTC.
- 산·상·엄·온·옷·옹·우의 수정 전후 70장을 비교하여 공통 비가시 결함 해소를 확인했다. [전후 미술 검토](BUFFER_REPAIR_REVIEW.md).
- 엄의 띠로 된 그릇 외피, 물의 연속 흐름 방향과 요격 맥락의 최종 검수는 남아 있다. 이전 120개 영상은 복구 이전 버전이므로 이 수정의 영상 증거로 사용하지 않는다.

## C2 실제 입력 검사

새 검수 도구는 기존 C2 PlayerRig에 가상 Mouse/Keyboard 입력을 전달한다. 등록된 자모 템플릿의 획을 실제 `DrawingInputController.Update`와 인식기로 보냈으며 인식 결과나 시전 이벤트를 직접 주입하지 않았다.

- 최신 [검사 결과](../../../Art/SpellVFX120/player_input_audit.json): 가·노·머 3종 모두 인식, 기존 DI 시전, 새 VFX 1개 생성, 실제 시계, 수명 종료를 관측했다. 오류 0·실패 0·잔여 효과 0.
- 입력 필터의 null과 빈 목록을 혼동하던 검수 도구의 복구 버그를 수정했다. 재검사에서 원래 바인딩·필터·장치·설정·카메라와 시간 배율 복귀, 임시 PlayerLoop 제거를 관측했다. 최초 실패 결과는 `player_input_audit_first.json`으로 보존했다.
- C2에는 이 검사에서 구성된 적이 0개다. 실제 피해/AI/반격 성공, 일반 필기 정확도, 전체 15자와 성능은 이 3종 검사로 통과 처리하지 않는다.
