# 오행부 맵 표현 및 생성 가이드
## 수묵담채화 기반 3D 월드 제작 파이프라인

> 목적: Unity 기반 3D 맵을 동양식 수묵담채화의 인상으로 통일하면서, 반복적인 산 모델 배치 문제를 줄이고 Codex + Unity MCP를 통한 맵 생성·배치 자동화가 가능한 구조를 정의한다.

---

## 1. 전체 비주얼 방향

현재 프로토타입은 다음 방식을 사용한다.

- Cell Shading 기반 렌더링
- Post Processing으로 한지색 적용
- 전체 채도 감소

이 방향은 유지하되, 단순한 "저채도 동양풍 툰 렌더링"이 아니라 **3D 수묵담채 산수화**에 가까워지도록 확장한다.

핵심 요소:

1. 먹의 농담
2. 불균일한 붓 경계
3. 제한적인 담채
4. 한지의 재질감
5. 거리에 따른 디테일 생략
6. 원경이 한지 속으로 녹아드는 표현
7. 자연물과 건축물의 선택적인 먹선

권장 렌더링 흐름:

```text
3D Environment
       ↓
Stylized Material
       ↓
Modified Cell Shading
 ├─ 2~3 Tone
 ├─ Ink Noise
 └─ AO Ink
       ↓
Selective Ink Outline
       ↓
Ink Wash Distance
 ├─ Saturation ↓
 ├─ Contrast ↓
 ├─ Detail ↓
 └─ Outline ↓
       ↓
Restricted Color Palette
       ↓
Hanji
 ├─ Paper Color
 ├─ Fiber
 └─ Absorption Noise
       ↓
Element / Magic VFX
```

---

# 2. 셀 셰이딩을 먹의 농담으로 확장

일반적인 셀 셰이딩처럼 명암 경계가 지나치게 깨끗하면 수묵화보다 애니메이션풍으로 보이기 쉽다.

따라서 Shadow Threshold에 World-space Noise를 결합한다.

```text
일반 Cell

████████│░░░░░░░


Ink Cell

██████▓▓▒ ░▒░░░░
```

권장 방식:

```text
Lighting
+
World-space Ink Noise
        ↓
Tone Threshold
```

Noise는 Screen Space보다 World/Object Space 기반을 우선한다. 카메라 이동 시 먹 무늬가 화면에 붙어서 움직이는 현상을 방지하기 위함이다.

---

# 3. 먹선 / Outline

모든 오브젝트에 동일한 검은 외곽선을 적용하지 않는다.

거리와 오브젝트 중요도에 따라 먹선 강도를 변화시킨다.

```text
근경
████ 강한 먹선

중경
▓▓▓ 중간 먹선

원경
░░ 약하거나 없음
```

권장 규칙:

- 캐릭터: 비교적 명확한 먹선
- 주요 건축물: 중~강
- 근거리 바위: 중간
- 나무/자연물: 약~중
- Terrain: 대부분 명암과 실루엣으로 표현
- 원경 산: 거의 없음

선의 두께에도 Noise를 적용해 일정한 디지털 선처럼 보이지 않도록 한다.

---

# 4. AO를 먹 표현으로 활용

Ambient Occlusion을 단순한 그림자가 아니라 **먹이 고이는 영역**처럼 사용한다.

예:

```text
평면       → 담묵
홈         → 농묵
깊은 틈    → 진한 먹
```

적용 대상:

- 기와 사이
- 암석 틈
- 건축물 접합부
- 나무뿌리
- 절벽 균열

개념적으로:

```text
AO × InkNoise
        ↓
Ink Density
```

---

# 5. 담채와 색상

전체 화면의 Saturation만 낮추는 방식보다 Material Palette 자체를 제한한다.

예시:

| 대상 | 기본 색 방향 |
|---|---|
| 소나무 | 회녹 |
| 흙 | 황갈 / 황회 |
| 기와 | 청회 |
| 목재 | 적갈 |
| 바위 | 회갈 / 청회 |
| 원경 산 | 담청 / 회청 |
| 마석·술법 | 상대적으로 높은 속성색 |

전체적인 인상은:

**먹 70~80% + 색 20~30%**

정도로 가져간다.

마석, 술법, 오행 속성처럼 게임 플레이상 중요한 요소만 상대적으로 높은 채도를 허용하면 환경과의 대비가 강해진다.

---

# 6. 한지 표현

한지 Texture 한 장을 화면 전체에 단순 Multiply하는 방식에서 확장한다.

```text
Hanji System

Paper Color
    → 전체 미색

Paper Fiber
    → 미세한 섬유질

Ink Absorption Noise
    → 먹 경계 변화
```

같은 Paper/Absorption Noise를 다음 요소에서 공유하면 화면 전체가 같은 종이에 그려진 것처럼 통일된다.

- Toon Shadow
- Outline
- Terrain Ink
- 원경 Fade
- VFX 일부

Paper Grain은 플레이어가 명확하게 텍스처라고 인식할 정도로 강하게 만들지 않는다.

---

# 7. 거리 기반 수묵 원근

일반적인 Fog만 사용하는 대신, 거리가 증가할수록 그림 자체가 생략되는 방식을 사용한다.

```text
Camera

근경
Detail 100%
Ink 100%
Color 80%

중경
Detail 60%
Ink 60%
Color 50%

원경
Detail 20%
Ink 20%
Color 20%

→ Hanji
```

Distance에 따라:

```text
Saturation ↓
Contrast ↓
Outline ↓
Texture Detail ↓
Ink Density ↓
Paper Color Blend ↑
```

이 효과는 Terrain과 Sky 사이를 하나의 그림처럼 연결하는 핵심 시스템으로 사용한다.

# 8. Terrain 기반 산 생성

기존 방식:

```text
Mountain_A
Mountain_B
Mountain_C
Mountain_A
Mountain_C
...
```

산 모델을 반복 배치하면 동일한 실루엣이 반복되어 인공적으로 보이는 문제가 발생한다.

따라서 **산맥·골짜기·평야·길 등 전체적인 지형은 Unity Terrain을 중심으로 구성**한다.

Terrain 생성 개념:

```text
Base Height Shape
+
Large Noise
+
Medium Noise
+
Erosion
        ↓
Terrain
```

Terrain을 사용하면 각각의 산을 독립 오브젝트로 취급하지 않고 하나의 연속된 산맥으로 설계할 수 있다.

---

# 9. Terrain 수묵 Shader

Terrain에도 수묵담채 Shader를 적용한다.

입력:

```text
Terrain Layers
Height
World Normal
Camera Distance
World Noise
Paper Noise
```

처리:

```text
Height Color
Slope Ink
Cell Lighting
Ink Breakup
Triplanar Brush
Distance Wash
Paper Blend
```

출력:

```text
Ink Wash Terrain
```

---

# 10. Terrain 경사 기반 절벽 표현

Terrain의 World Normal을 이용해 Slope를 계산한다.

예시 규칙:

```text
Slope < 25°
→ 흙 / 풀 / 담채

25° ~ 55°
→ 바위 + 중간 먹

55° 이상
→ 절벽 Material
→ 진한 농묵
→ Triplanar Brush
```

급경사일수록 먹 농도를 높인다.

개념:

```text
Height
+
Slope
+
World Noise
        ↓
Ink Density
```

절벽 Texture는 Triplanar Mapping을 활용해 급경사에서 UV가 늘어나는 문제를 줄인다.

---

# 11. Terrain의 구조적 한계

Unity Terrain은 Heightmap 기반이므로 하나의 XZ 좌표에 하나의 높이만 존재한다.

따라서 다음 구조는 Terrain만으로 만들기 어렵다.

- Overhang
- 동굴
- 안쪽으로 파인 절벽
- 완전한 수직 암벽
- 거대한 돌출 암반

따라서 모든 지형을 Terrain으로 해결하지 않는다.

---

# 12. Terrain + Cliff Mesh 하이브리드

권장 비율:

**Terrain 약 80% + Cliff/Rock Mesh 약 20%**

Terrain 담당:

- 산맥
- 능선
- 골짜기
- 평야
- 길
- 일반 경사

Mesh 담당:

- 수직 절벽
- 오버행
- 동굴 입구
- 돌출 암반
- 플레이어가 가까이 접근하는 중요한 절벽

구조:

```text
             Terrain
          ___──────
       __/
      /
     │█████
     │█████ ← Cliff Mesh
     │█████
     │
_____/ Terrain
```

---

# 13. Cliff Module

산 전체를 하나의 Mesh Asset으로 만들지 않고 절벽을 모듈화한다.

예:

```text
Cliff_Straight_A
Cliff_Straight_B

Cliff_Convex_A
Cliff_Concave_A

Cliff_Tall_A

Rock_Large_A
Rock_Large_B
```

같은 Mesh라도 다음 요소를 변화시켜 반복감을 감소시킨다.

```text
Mesh
+
Scale Variation
+
Rotation Variation
+
World-space Ink Noise
+
Terrain과 일부 겹침
```

World-space Ink Noise를 사용하면 같은 암벽 Mesh라도 위치에 따라 먹 무늬가 달라진다.

---

# 14. 산 표현의 5단 구조

```text
Level 1
Terrain
→ 전체 산맥 / 계곡 / 길 / 평야

Level 2
Cliff Mesh
→ 중요한 절벽

Level 3
Rock Props
→ 바위 / 암석 / 돌출물

Level 4
Ink Shader
→ 먹 / 붓 터치 디테일

Level 5
Vegetation
→ 소나무 / 풀 / 덤불
```

권장 개념:

**Terrain = 산**  
**Cliff Mesh = 절벽**  
**Rock Props = 근거리 디테일**  
**Shader = 수묵 표현**  
**Background Mountain = 원경 실루엣**

---

# 15. 절벽의 붓 터치

절벽은 사실적인 암석 Texture에 의존하기보다 세로 방향 붓 터치를 섞는다.

```text
       ╱╲
      ╱  ╲
     ╱│▓│╲
    ╱ ▒│▓ ╲
   │▓│ ▒│▓│
   │▒│▓ │▒│
```

이를 통해 비교적 단순한 Geometry에서도 복잡한 수묵 암벽처럼 보이게 한다.

# 16. 자연물 표현

## 나무

사실적인 PBR foliage보다 잎을 붓점/붓 터치 덩어리처럼 표현한다.

```text
     ▓▒
   ▓▒▓▒▒
  ▒▓▒▓
     │
    ╱│╲
```

권장:

- Alpha Cutout
- Ink Noise
- 제한된 회녹 Palette
- 개별 잎보다 덩어리 실루엣 우선

## 풀

개별 풀잎의 사실성보다 붓으로 `///` 그은 것 같은 실루엣을 우선한다.

---

# 17. 물과 폭포

사실적인 PBR Water보다 담채화에 맞는 단순화된 표현을 사용한다.

물:

- 회청 / 담청
- 약한 Reflection
- 흐르는 먹선
- 약한 Distortion
- 제한적인 Highlight

폭포:

- Particle 대량 사용보다 세로 Brush Texture
- Flow Shader
- 먹/한지 Noise 활용

# 18. Skybox 기본 철학

사실적인 HDRI Skybox는 사용을 최소화한다.

하늘을 별개의 사실적인 공간으로 표현하기보다 **산수화의 여백 / 한지**로 취급한다.

전체 구조:

```text
Camera
 │
 ├─ Terrain / 건축물
 ├─ Distance Ink Fog
 ├─ Background Mountains
 ├─ Ink Clouds
 └─ Hanji Sky
```

---

# 19. Hanji Procedural Sky

기본 Sky는 따뜻한 회백색/미색을 기반으로 한다.

```text
천정
옅은 회청
     ↓
수평선
한지 미색
```

추가:

- 약한 Paper Fiber
- 약한 Sky Gradient
- 강한 사실적 대기 산란은 지양

# 20. 수묵 구름

Volumetric Cloud보다 Ink Noise 기반 구름을 우선 고려한다.

```text
Noise A
+
Noise B
(다른 속도로 이동)
        ↓
Cloud Mask
        ↓
Soft Edge
        ↓
담묵 Cloud
```

구름은 매우 천천히 움직이고, 흰색 덩어리보다 먹의 농도를 변화시키는 형태에 가깝게 표현한다.

---

# 21. 원경 산

Skybox에서 가장 중요한 요소 중 하나.

원경 산은 실제 거대한 Terrain/산 Mesh 대신 다음을 사용할 수 있다.

- Mountain Card
- Low-poly silhouette mesh
- 수묵 산 Alpha Texture
- 여러 Layer의 Parallax Background

예:

```text
Foreground       ███████

Mid Mountain       ▓▓▓▓

Far Mountain          ▒▒▒

Very Far                  ░░░

Hanji                        .
```

권장:

```text
Mountain_Far_A
Mountain_Far_B
Mountain_Far_C
```

등 3~5종의 실루엣을 조합하고 거리·크기·농도를 변화시킨다.

---

# 22. Terrain과 Sky의 연결

Terrain과 Skybox의 경계가 보이면 그림처럼 느껴지지 않는다.

일반적인 경계:

```text
Terrain
██████████████│ Sky
```

목표:

```text
Terrain
████████▓▓▓▒▒░░░

             ░ Far Mountain

                   Hanji
```

Distance Ink Fog를 이용해 Terrain이 한지 속으로 녹아들게 한다.

```text
Distance ↑

Contrast ↓
Saturation ↓
Ink Density ↓
Detail ↓
Hanji Blend ↑
```

# 24. 해와 달

사실적인 천체보다 단순한 도형적 표현을 사용한다.

```text
         ◯

      ░░△░░
   ░△░      ░△
```

- 해: 제한적으로 높은 채도의 붉은 원
- 달: 한지보다 밝은 담백한 원

환경 전체가 저채도일수록 이러한 제한적인 색상이 강한 시각적 포인트가 된다.

# 27. Codex 자동화 시 역할 분리

Codex에게 "예쁜 맵을 알아서 만들어"라고 지시하기보다 역할을 명확하게 나눈다.

## 자동화하기 좋은 영역

- Terrain Heightmap 생성/수정
- 경사도 분석
- Cliff 후보 영역 탐색
- Rock/Vegetation Scatter
- 반복 배치 Randomization
- Terrain Material 적용
- Shader Parameter 설정
- 원경 산 Layer 배치
- Validation
- 플레이 가능 경사 검사

## 사람이 결정해야 할 영역

- 랜드마크 위치
- 주요 산의 실루엣
- 플레이어 시선 유도
- Vista
- 주요 길

# 28. 반복 방지 규칙

맵 자동 생성 시 같은 산/암벽/자연물이 반복되어 보이지 않도록 다음 규칙을 적용한다.

```text
Variation =
Mesh Variant
+ Rotation
+ Scale
+ Position Offset
+ World Ink Noise
+ Vegetation Mask
+ Partial Terrain Embedding
```

단, 랜덤화를 무제한으로 적용하지 않는다.

큰 실루엣과 주요 랜드마크는 의도적으로 설계하고, 작은 디테일만 Procedural Variation을 사용한다.

# 31. 핵심 원칙 요약

맵 전체를 사실적인 3D 공간에 한지 필터를 씌운 것으로 만들지 않는다.

대신 각 계층이 수묵담채화의 역할을 담당하도록 한다.

```text
Terrain
= 산수화의 큰 형태

Cliff / Rock
= 준법과 암석 디테일

Shader
= 먹과 붓

Color
= 담채

Fog
= 먹의 농담과 원근

Sky
= 한지의 여백

Far Mountain
= 원경 산수

오행 VFX
= 제한적으로 강한 색채
```

최종 목표는 **"수묵 필터가 적용된 3D 게임"이 아니라 "플레이어가 움직일 수 있는 3D 수묵담채 산수화"**로 잡는다.
