# 플레이테스트 개선 통합 기록

이 자료는 선택한 A 파지, 이동·착석, 먹 흡수·소리, 식생과 지도 변경을 함께 검토하기 위한 기록이다. 기존 외형과 공급자 원본을 보존한 파생 자산을 별도 플레이테스트 씬에 연결했다. 전체 월드를 다시 생성하지 않았다.

## 적용 내용

- **손:** A의 감싸 쥐는 파지를 실제 C02 손에 제작했다. 1인칭에서 엄지와 손가락이 소매에 가려지던 문제는 붓과 손의 축 회전 −162°로 조정했다. −192° 비교도 보존했다. 이 각도는 제작자가 실제 화면을 보고 정한 값이며, 사용자의 최종 비주얼 승인을 뜻하지 않는다.
- **이동:** 걷기 2.2m/s, Ctrl 달리기 5.5m/s, Space 약 0.75m 점프, C 앉기·일어나기를 연결했다. Shift 회피는 유지한다. 기존 동작을 C02의 고정 길이 다리에 맞췄으며, Blender에서 만든 정확한 변형을 기존 Avatar에 구워 Humanoid 변환 때 팔·골반 위치가 어긋나던 문제를 수정했다. 바닥 착석에 회복·저장 효과는 없다.
- **먹·소리:** 주 먹줄기 하나와 가는 먹결 두 개가 실제 효과용 붓끝에 수렴한다. 양수 증가량만 HUD의 늘어난 구간을 강조한다. 파생 PCM, 효과별 재생 상한, 믹서와 짧은 페이드, 갈무리 시작·루프·종료를 연결했다.
- **식생:** 5강토의 군락을 늘리고 길·입구·계단은 제외했다. 보유 에셋의 풀·관목·수목과 같은 위치의 원거리 카드를 사용한다. 하얗게 보이던 용머리 식생의 색·노멀·투명도 누락을 복구했다. 가까운 밀도를 유지하면서 원거리 관목을 카드로 바꾸고 화면 밖 개체의 제출과 먼 그림자를 줄였다.
- **지도:** 실제 지리를 기준으로 삽화 지도를 만들었다. 큰 지리는 처음부터 보이고 세부는 탐험에 따라 공개된다. 미니맵에는 실제 높이에서 굽힌 등고·기복 타일을 사용한다. 기존 가로·세로 종이 펼침과 실내 지도는 유지한다.

## 발 접촉 검사와 남은 범위

`Locomotion/Reports/unity_synthetic_feet.json`의 2026-09-14 02:10:21 UTC 결과를 사용했다. 현재 C02와 실제 보정 솔버에 단일 동작, 정해진 이동량, 진단 평면을 입력한 30개 조건이다. 실시간 블렌드 트리·실제 경사 충돌 속도·지형 Raycast·OS 입력을 검사한 결과는 아니다.

원장의 엄격 기준은 **26/30 통과**이며 상태는 `FAILED_LIMITS`로 남겨 두었다. 사용자가 정한 **미끄러짐 100mm 이내·관통 20mm 이내**로 같은 측정값을 비교하면 **30/30 통과**한다. 최대 지지 구간 미끄러짐은 **55.17mm**, 최대 Foot+Toes 가중치 정점 관통은 **18.928mm**다. 코드의 검사 문턱을 완화하거나 실패 기록을 지우지 않았다.

남은 네 실패는 모두 `RunForward`, 12° 진단 경사에서 독립적인 Foot+Toes 피부 검사의 **15mm 미만** 조건을 넘은 경우다.

| FPS | 시간 배율 | 최대 관통 |
|---:|---:|---:|
| 30 | 0.2 | 16.332mm |
| 60 | 0.2 | 18.044mm |
| 120 | 1.0 | 15.504mm |
| 120 | 0.2 | 18.928mm |

이 검사는 Foot+Toes 합산 웨이트가 0.5 이상인 정점을 휴식 자세 높이로 제외하지 않고 검사하므로, 발 웨이트가 걸린 옷자락 정점도 포함할 수 있다. 전체 옷감의 무관통이나 실제 보행 완료를 뜻하지 않는다. 실제 키 입력·언덕·계단·착지와 사용자 보행은 계속 미검증으로 남긴다.

## 식생 성능

동일한 실제 플레이 카메라·1920×1080·정지 위치에서 180프레임을 측정했다. 이전 배치는 **현재 렌더러**로 표시한 비교이며 과거 실행 파일이 아니다. 이전에 비활성 검토 카메라로 측정한 0 draw 결과는 무효 처리했다.

| 상태 | CPU 중앙값 | GPU 중앙값 | 제출 part-instance |
|---|---:|---:|---:|
| 이전 배치 | 6.06ms | 3.21ms | 6,325 |
| 고밀도, 최적화 전 | 19.66ms | 19.55ms | 97,307 |
| 고밀도, 관목 카드·가시성·그림자 조정 후 | 9.53ms | 5.96ms | 58,815 |

최적화 후 CPU p95는 11.68ms, GPU p95는 6.11ms다. Unity 할당 메모리는 약 4,701MiB, 측정 시 시스템 커밋은 약 59%였다. 이 값은 전체 구간·이동 중 최악값이나 standalone 프레임 보장이 아니다. 식생 밀도 자체는 유지했다. 원장은 `Vegetation/Performance/forest_comparison.json`에 있다.

## 전달·남은 항목

`REVIEW.html`에서 손·식생·지도 화면, 먹 연출, 효과음 비교와 분야별 보고서를 열 수 있다. 검사는 합성 입력, 실제 렌더, 수치, 사용자 비주얼 판단을 구분했다. 영상과 자동 보행 완주는 제작하지 않았다. 통합 검사 후 Windows 후보를 **한 번 생성**했고 기존 빌드는 보존했다.

### 최종 Windows 빌드 후보

- 폴더: `Builds/Playtest-20260915/20260914T022453Z`
- 실행 파일: `Oheangbu_Playtest.exe`. 배포할 때 실행 파일 하나가 아니라 해당 폴더 전체가 필요하다.
- Unity 6000.3.9f1 · Windows x64 · Mono, 2,546,383,730 bytes, 빌드 58.45초, 오류 0.
- 경고 582건: 리소스 패키징 셰이더 경고 555, 스크립트/빈 패키지 어셈블리 경고 26, 사용되지 않는 RuntimePipelineManager 관련 전처리 경고 1. 상세는 폴더의 `release_build_report.json`과 `build.log`에 보존했다. 경고를 숨기거나 공급자 코드를 변경하지 않았다.
- 테스트 저장 슬롯 해제, 최종 A/이동 프리팹 연결, 씬 저장, 기존 Build Settings의 목록과 파일 내용 복원 확인. 빌드 시작 커밋 약 58%.
- 동일 실행 파일을 숨김 창에서 D3D12와 D3D11로 시작했다. 둘 다 기대 로비 씬과 UI 객체에 도달했고 수집한 런타임 오류·경고는 0이었다. 입력·저장·보행·게임플레이를 실행하지 않았고 검사 후 프로세스는 종료됐다.
- **일반 창의 화면 표시와 실제 플레이는 미검증이다.** 두 숨김 실행의 PNG가 모두 검은색이었다. 진단 도구의 원시 `PASS_STANDALONE_TITLE_STARTUP_ONLY`는 객체 준비와 PNG 형식만 확인하므로 화면 표시의 통과 근거로 사용하지 않는다. 화면을 확인한 별도 평가가 우선하며, 이 결과만으로 일반 실행도 검은 화면이라고 단정하지 않는다.

이 후보는 외부 플레이테스트 QA 완료판이 아니다. 아래 미검증 범위와 CPU 성능 미달을 포함해 사용자 확인이 필요하다.

실제 키 입력의 걷기·경사·계단·착지, 가장자리 연속 작도, 전 지역 LOD 경계 이동, 장치 SFX 청취, 전체 보행과 독립 빌드 성능은 미검증이다. 기존 차량 저장은 마지막 안전 보행 위치를 사용하므로 주행 도중 종료하면 차량 현 위치에서 이어지지 않는다. 이번 이동 개선에서 차량 위치 저장 정책은 확장하지 않았다.
