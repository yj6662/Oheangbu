## 확인한 원인과 변경

기존 Overhand ArmPole은 손의 전방 축을 거꾸로 연장해 팔꿈치 방향을 정했다. 따라서 붓·손목의 회전에 팔꿈치 굽힘 평면까지 따라 돌아갔다. 별도로 근접 팔의 깊이·붓 각도 탐색은 매 프레임 독립적인 격자 후보만 비교해, 거의 같은 포인터 위치에서 다른 해로 전환할 수 있었다. 실제 가상 입력 Play에서 프레임 사이 팔꿈치가 최대 28.0cm 이동했다.

- 몸통/근접 카메라 기준 아래쪽과 약한 바깥쪽 방향으로 팔꿈치 평면을 분리했다. 손등 위·붓털 엄지 방향·엄지 감싸기는 유지한다.
- 근접 후보 비용에 팔꿈치 높이와 과도한 접힘을 반영했다.
- 이전에 채택한 각도·깊이 주변의 작은 후보도 탐색하며, 팔꿈치·각도·깊이가 급격히 바뀌는 후보에는 비용을 준다. 기존 전체 탐색도 남겨 도달 가능성을 확인한다.
- 원시 포인터와 획은 평활화하지 않는다. 현재 포인터 광선 위에서 표현 깊이와 팔 자세만 선택한다. 팔·붓 길이를 늘리지 않으며 근접 어깨 추가 이동 상한 5cm를 유지한다.
- 근접 팔이 숨겨지면 이전 해를 초기화한다. 자동차 오행부 동작과 보행 모션은 기존 경로를 유지한다.

`StableDrawingElbow`를 현재 PlayerGesture_GripA에 활성화했다. 이전 소스와 프로필은 Before에, 방향만 변경했던 중간 단계의 검사 결과는 IntermediateDownPole에 보관했다. 중간 단계는 연속 검사에서 손목 47.35°와 팔꿈치 급변이 남아 최종본으로 채택하지 않았다.

정확한 값은 comparison.json에 있다. 동일 7초 곡선 경로를 가상 Q·왼쪽 마우스로 실제 InputSystem Dynamic 갱신에 전달했다. 실제 Unity PlayerMotor·DrawingInput·카메라·브러시·IK 프레임을 사용했다. Game View는 사용 중이던 2560×1440이다. Editor 프레임 간격과 표본 수는 다르므로 고정 FPS의 일대일 프레임 비교로 주장하지 않는다. 인접 이동 집계에는 관측 간격 80ms 미만을 사용했으며 전체 프레임과 제외되지 않은 자세 최대값도 원장에 남겼다. 성능 벤치마크가 아니다.

미완성 획은 메뉴의 실제 취소 경로로 정리했다. 인식 커밋·자동차 호출·자동 보행은 발생시키지 않았다. 입력 장치·프로필·메뉴와 시간 상태를 복원했다. 플레이어 저장은 격리 슬롯만 사용하고 종료 후 시험 슬롯을 해제했다.

별도 1080p 진단 카메라의 중앙·네 모서리·네 변 및 복원 검사 **96항목 통과**. 붓끝 2px, 손목 45°, 손등 방향, 엄지 방향, 본 길이, 반복 파지·일시정지·재활성화 등을 포함한다. 이 96개는 동기 합성 자세 검사이며 실제 연속 입력 결과와 구분한다.

## 화면 확인과 제한

중앙 전후 정지 이미지를 확인했다. 오른쪽 위 극단에서는 손이 화면 밖으로 나가는 기존 구성 문제가 남아 있다. 해당 이미지를 팔이 잘 보인다는 통과 증거로 사용하지 않는다. 전신에서는 손목이 소매에 가려지는 기존 웨이트·형상 문제가 남아 있으며, 이번 변경으로 메시를 재제작하지 않았다.

- 통과: 이번 연속 획에서 과도한 상향 팔꿈치와 큰 자세 전환 감소, 기존 추종/파지 수치 유지.
- 미완료: 화면 극단의 손 가시성, 손 메시·소매 및 자동차 판 접촉의 최종 외형.
- 미검증: 사람의 직접 작도 체감, 웅크림·모든 카메라 피치·이동/피격/갈무리 전환의 이번 버전 연속 검사, 전체 메시 면 관통, 목표 FPS별 반복 검사.
- 전체 작업 공백은 GAP_AUDIT.md에 별도로 정리했다. 원본 보존, 영상·반복 빌드 없음.
