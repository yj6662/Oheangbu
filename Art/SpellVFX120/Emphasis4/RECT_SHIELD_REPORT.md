# 사각 문양 방패와 접점 폭발 v6

2026-09-10. 사용자 요청에 따라 거·너의 방어 형상과 접점 반응, 가·나의 발사 위치를 수정한다. 이전 v5 프로필·영상과 KTP 공급자 원본은 보존한다.

[이전/수정 비교 페이지](http://127.0.0.1:8771/RECT_SHIELD_REVIEW.html)

## 변경

- **거·너 방패:** 폭1.8m × 높이2.2m의 사각 반투명 면과 얇은 테두리, 중앙 KTP Bottom04/09 문양. 중앙 문양의 명목 크기는1.05m다. 방패가 직접 펼쳐지므로 별도 발동 원형을 중복 생성하지 않는다.
- **방어 접점:** 작은 문양 입자1개를0.3초간 빠르게 확대·소멸시키며 기존 속성 입자와 함께 재생한다. 명목 문양 크기는 약0.64m로 방패보다 작다. 별도 복사 재질과 알파 곡선으로 가시성을 보강했다.
- **목 반응:** 나뭇조각·잎과 작은 문양 폭발을 함께 사용한다.
- **화 반응:** 짧은 화염·불티 뒤 재 조각이 흩어지며 작은 문양 폭발을 함께 사용한다. 투사체 원본 메시를 재로 바꾸는 디졸브가 아니라 기존 제거 시점에 맞춘 입자 표현이다.
- **가·나 출발점:** 화면 좌표(0.6667,0.3333)→(0.60,0.40). 중심으로부터 가로·세로 간격을 각각40% 줄였다. 깊이1.6m, 표적·착탄 시점, 이전 확대 명중 효과는 유지한다.

방패는 깊이 검사를 하는 월드 오브젝트다. 사각 면은 URP 투명 셰이더를 쓰고, KTP 중앙 문양과 접촉 문양은 공급자 원본에서 파생한 별도 프리팹/재질이다. 중앙 문양과 사각 면은 합계2개의 입자로 표현하고 방어 수명에 따라 정리한다. 성공/반성공 접점은 기존 단일 접촉 생성 경로를 유지한다.

중앙 문양은 원본 셰이더의 normalized custom-data 펼침 곡선을 펼쳐진 구간(0.35)으로 고정하고, 알파0.8까지 빠르게 드러나게 했다. 긴 방패 수명 때문에 원본의 펼침 시간이 수초로 늘어나 중앙이 비어 보이던 중간 시안을 수정한 것이다. 접촉 문양은 별도로 짧은 곡선을 재생한다. 공급자 원본의 곡선과 재질은 바꾸지 않았다.

## 검토 파일과 한계

`가_v6`, `나_v6`, `거_v6`, `너_v6`에 각각 이전/수정 × 플레이/외부 구도, 설정, 실행 보고서를 저장한다. 새 프리팹은 `RectShield_0/1`, `SmallPatternContact_0/1`, 새 재질/메시는 `RectShieldPanel`, `SmallPattern_0/1`, `ShieldQuad`다. 이전판은 `BaselineV5_*.asset`으로 보존한다.

영상은1080p·24fps·각6초. C2의 시험 표적/입사 신호를 사용하며 실제 피해·방어 판정·입자 Update 경로를 실행한다. 손글씨 입력부터 실제 적 AI까지 연결한 전투 영상은 아니다. 전체 카메라 이동·벽 근접·다중 시전 성능·최종 미술 합격은 미검증이며 사용자 검토 대상이다.

## 메모리 중단과 재개

나 촬영 중 다음 클립 시작 시 커밋 사용률85% 기준에 걸려 자동 중단됐다. 최초 중단 보고서는 `나_v6/memory_stop.json`에 보존했다. 사용하지 않는 에셋/GC 정리만으로 충분하지 않아 재시도도 새 클립 시작 전에 중단했다.

읽기 전용 프로세스 조사에서 에셋 임포트 작업자2개가 각각 약11GB를 사용 중임을 확인했다. Unity의 [ForceToDesiredWorkerCount](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/AssetDatabase.ForceToDesiredWorkerCount.html)로 유휴 작업자를 정리하고 DesiredWorkerCount는 기존3으로 즉시 복원했다. 이후 측정된 시스템 커밋은35,233,996,800/67,893,133,312바이트, 약51.9%였다. 메인 에디터·씬·OS 설정은 유지했다.

촬영 도구는 각 클립의 렌더 자원을 해제한 뒤 GC와 사용하지 않는 에셋 정리가 끝나기를 기다리고 다음 클립의85% 검사를 수행한다. 작업자 정리는 별도의 명시적 도구 명령이며 일반 플레이 때 자동 실행하지 않는다.
