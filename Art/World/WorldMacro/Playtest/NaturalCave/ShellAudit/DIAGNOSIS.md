# 폐광 외피 진단 — 2026-09-15

사용자가 보고한 ‘처음 폐광에 뚫린 메시가 많음’을 **현재 기본 외피의 큰 삼각형 누락으로는 아직 재현하지 못했다.** 다방향 화면에서 별도로 확인한 **입구 바닥의 삼각형 돌출·중첩**은 수정했다. 두 문제를 같은 원인으로 단정하지 않는다. 기존 바닥 지지 검사만으로 벽과 천장이 닫혀 있다고 보고하지 않고, 저장 메시와 실제 Unity 충돌 표면을 별도로 조사했다.

## 확인한 바닥 결함과 수정

`join-left.png`의 첫 촬영에서 실내 바닥과 벽 접점에 톱니처럼 솟은 검은 삼각형을 확인했다. 접근 흙 메시가 X=-54부터 시작해 이미 완성된 실내 바닥(X≤-43)과 약 11m 중첩되고 있었다. 그중 내부에 실제로 참조되는 정점 4개가 Y=0.10m보다 높았고, 최대 약 0.633m까지 솟았다. 측면 바닥을 만들 때 포털 벽의 높이를 바닥으로 받아들인 흔적이다.

기존 `Continuous_Approach_Soil 4.asset`을 보존하고 다음 두 파생본을 순서대로 만들었다.

1. `Continuous_Approach_JoinedToInterior.asset`: 접근 흙의 X<-43.02 부분만 정확히 제거하고, 입구 접합선을 실내 바닥의 Y=.03에 연결했다. 삼각형 3,200→2,808개, 정점 5,355→1,511개. 실내 외피·실내 바닥·포털 메시·게임플레이 위치는 유지했다.
2. `Continuous_Approach_JoinedToInterior_SoftJoin.asset`: 첫 시도에서 0.8m의 높이 혼합이 실제 1m 격자의 다음 정점 전에 끝나, 삼각형의 직선 보간이 접점 근처에서 너무 급하게 올라가는 문제를 확인했다. 현재 적용본은 X[-43,-39]의 실제 정점 네 열에 걸쳐 높이를 혼합한다. 62개 정점만 조정했으며 삼각형 수 2,808개는 유지한다. 앞 파생본도 보존한다.

**접합부 30cm 폭 지지 검사: 80개 단면·560개 표본 중 560개 지지, 해당 폭의 최대 높이 변화 약 2.59cm로 통과.** 첫 시도의 최대 16.55cm 변화 실패와 기준은 `approach_validation-first.txt`에 남겼으며 통과를 위해 검사 기준을 느슨하게 바꾸지 않았다. 이 값은 폭 안에서의 연속 높이 변화이며 발 관통이나 실제 보행 측정은 아니다. 새 렌더 메시와 충돌 메시가 같은 파생 에셋을 참조한다.

최신 `join-left.png`에서 중앙의 뾰족한 중첩이 줄어든 것을 확인했다. 오른쪽 입구의 바닥과 암벽 재질이 만나는 거친 형태는 일부 남아 있으므로 미술 최종 합격으로 처리하지 않는다. `join-right.png`와 `start-left.png`는 수정 전 외피를 조사한 이미지이며, 최신 바닥 적용 검증 사진과 혼동하지 않는다. 기존 원본 에셋으로 변경 이전 형태를 재현할 수 있지만 모든 방향의 전후 이미지가 완비됐다고 보고하지 않는다.

수정 원장: `approach_repair.txt`, `approach_refinement.txt`, `approach_validation.txt`.

## 실제 확인

- 저장된 `Natural_Cave_EmbeddedInterior.asset`과 `Natural_Cave_InnerFloor.asset`을 읽은 Blender BVH 검사: 높이 1.1·1.65·2.35m의 유효 지점 406개, 77,952방향. 막힌 표면 76,897회, 입구 방향 1,055회, 예상하지 않은 누출 0, 반대 방향 법선 명중 0. `../shell_offline_rays.json` 참조.
- Unity Edit 실제 MeshCollider 검사: 398개 지점, 76,416방향. 막힌 표면 75,379회, 의도한 입구 1,037회, 예상하지 않은 누출 0. `Physics.queriesHitBackfaces` 켬/끔에서 처음 명중 면 차이 0. `survey.txt` 참조.
- 현재 CombatConfig의 숄더 오프셋 `(0, 0.55, -2.8)`, 충돌 구 반경 0.25m, near plane 0.08m를 사용했다. 가까운 벽을 포함한 152지점·5,472 회전/피치 조합에서 카메라 중심의 벽 통과 0, near-plane 모서리 통과 0.
- 두 기본 표면은 활성 상태이고, Renderer와 MeshCollider가 같은 에셋을 참조한다. CaveRock 재질은 이미 Cull Off이며 전역 양면화로 해결할 문제가 확인되지 않았다. 저장 씬에 occlusion bake 데이터도 없다.
- 주 외피의 바닥 경계는 별도 바닥 메시 경계와 일치한다. 정점 좌표를 0.1mm로 양자화한 토폴로지 검사에서 지붕의 약 0.1mm 크기 퇴화 경계와 일부 짧은 비정상 엣지가 발견됐으나, 이것을 보고된 큰 구멍들의 원인으로 판정할 수 없다.
- 기존 폐광 저장 위치를 실제 Play에서 불러온 후 현재 활성 `Main Camera`의 위치와 렌더 설정을 그대로 복사해 `runtime-current.png`를 1920×1080으로 촬영했다. 폐광 로컬 발 위치는 `(-136.0001, .0600, 4)`, 카메라는 `(-138.8, 2.16, 4)`였다. 실제 이미지를 열어 확인했을 때 가까운 벽·천장·바닥은 연속적으로 보였고, 먼 의도된 출구 외에 뚜렷한 큰 구멍은 보이지 않았다. 촬영 당시 시스템 커밋은 약 79.57%였다.
- 같은 Runtime 기록에서 기본 외피와 바닥은 모두 활성·카메라 마스크 포함·셰이더 지원 상태였다. 두 표면은 정적 배치에 합쳐지지 않았고, 각각 렌더 메시와 충돌 메시가 같았다. 검토용 `Macro_Review_Camera`는 비활성 상태였다. 이는 해당 시작 위치의 실제 Play 상태를 확인한 결과이며 전체 폐광의 화면 검증은 아니다.

## 확인 범위의 한계

전방위 검사는 X=-43의 의도한 입구를 허용한다. 입구 밖의 국부 산·지형 접합 전체를 밀폐된 방으로 판정하지 않는다. 수치 검사는 입력을 통한 실제 이동·카메라 조작을 대신하지 않으며, Runtime 화면 확인은 위 한 시작 위치에서만 수행했다.

`start-*.png`, `join-*.png`는 여러 방향의 Editor 환경 시안이다. `runtime-current.png`는 실제 Play의 현재 카메라 위치를 복사한 별도 검사이며, 그 위치·카메라·재질·정적 배치 상태는 `runtime-current.txt`에 기록했다. 씬의 Source Camera, 플레이어, 지형은 진단 촬영을 위해 옮기지 않았다. UI와 화면 합성이 별도 경로인 점, 실제 사용자 입력을 대신하지 않는 점은 구분한다.

사용자가 보고한 큰 외피 누출은 현재 **미재현** 상태다. 실제로 확인한 접근 바닥의 중첩은 위와 같이 수정했다. 재현 좌표 또는 실제 문제가 보이는 Play 화면을 확보해야 남은 증상의 원인을 정확히 좁힐 수 있다. 근거 없이 동굴을 다시 만들거나 입구를 막는 처리는 하지 않았다.
