# 관청에서 시작하는 첫 여정 — 통합 기술 보고서

2026-09-15

새 게임을 **마을 관청 앞 → 아전에게 폐광 조사 의뢰 확인 → 오행부 메뉴로 마석 자동차 호출 → 폐광 현장 조사** 흐름으로 연결했다. 기록첩 화면을 제거했고, 효과음의 프레임 의존 페이드를 수정했다. 폐광에서는 실제로 확인한 입구 바닥 중첩을 고쳤으나, 사용자가 보고한 큰 벽·천장 구멍은 현재 검사에서 재현하지 못했으므로 해결 완료로 판정하지 않는다.

이 보고서의 통과는 기록된 검사 범위에 한정한다. API 진단, 저장 정책 검사, 정지 화면 확인은 실제 사용자 입력 완주·앱 재실행·장치 청취를 대신하지 않는다. 화면 자료와 촬영 위치는 함께 제공한 검토 페이지에서 구분한다.

## 시작 목적과 관청 배치

처음에 확인할 대상은 관청 아전이다. 짧은 도입 내용과 현재 목적을 표시하고, 실제 대화 상호작용 `village_commission`을 마치면 자동차를 부르는 다음 단계로 넘어간다. 의뢰는 폐광 폭파 흔적을 살펴보라는 목적을 전달하며 배후나 사건의 정답을 설명하지 않는다. 대화 보상 통보는 0이며, 이 단계에서 임의의 경제 보상을 추가하지 않았다.

새 시작 위치는 월드 좌표 약 `(1911.10, 133.30, 645.90)`이다. 캡슐의 지지면과 비어 있는 공간을 검사했고, 아전이 첫 상호작용 반경 안에 있음을 확인했다. 기존 폐광 시작 좌표를 덮어쓰지 않고 선택 가능한 관청 오프닝 프로필로 분리했다.

관청은 보유한 `SM_Naeposa` 소형 한옥을 재사용한 **외관 시안**이다. 약 49만 삼각형인 집사청 원본 대신 약 9천 삼각형의 소스를 선택했으며, 현재 관청·마당·소품의 표시 메시 합계는 **22,307 tris**로 기록됐다. 완성된 관아 건축 전체나 실내 콘텐츠를 의미하지 않는다. 아전은 기존 NPC 대체 외형이며, 전용 얼굴·의상·음성 제작은 하지 않았다.

기록첩의 메뉴와 화면 경로는 제거했다. 조사를 완료했다는 사실과 NPC 대화의 기존 완료 ID는 저장 호환을 위해 유지한다. 소지품·술식 도감·지도와 대화 내용창은 계속 사용할 수 있다.

## 자동차 호출과 오행부 메뉴

현재 메뉴에 **마석 자동차 부르기** 버튼을 연결했다. 새 여정에서는 의뢰를 확인하기 전까지 버튼과 콜백 모두 호출을 거절한다. 기존 저장에는 새 의뢰를 강제로 부과하거나 호출 기능을 다시 잠그지 않는 정책을 적용했다.

호출은 기존 차량 한 대의 위치만 바꾼다. 도로 데이터의 `Carriage=true`인 큰길에서 가까운 후보를 고르고, 실제 지지면·경사·차체 및 바퀴 공간·승하차 공간·수면 높이·벽에 가려지는지 확인한다. 운전자 탑승, 차량 이동, 비어 있지 않은 위치, 즉시 반복 호출 등은 거절한다. 실패한 호출은 차량 위치를 바꾸지 않는다. 차량 인스턴스, 주행 프로필, 좌석과 바퀴를 새로 만들거나 초기화하지 않는다.

격리된 실제 Play API 진단에서 자동차는 기존 위치 약 `(1990.49, 133.23, 708.49)`에서 큰길의 약 `(1935.67, 133.15, 628.63)`으로 호출됐다. 같은 차량 ID와 프로필을 유지했고, 호출자의 전방에 반하는 방향으로 돌아서지 않는 것을 확인했다. 진단 종료 시 플레이어와 자동차는 원래 위치로 복원됐다. 이는 시험 중 확인된 위치이며, 모든 호출 위치를 그 좌표로 고정한 것이 아니다.

사용자가 제공한 **금빛 5소켓 오행부의 3D 메뉴 모델**과 새 차량 소환 VFX는 아직 제작하지 않았다. 이번에 연결한 것은 현재 메뉴에서의 기능이다. 또한 큰길은 호출 위치를 선정하는 조건이며, **큰길 밖 주행 강제 제한·자동 하차·도로 자동 운송은 구현하지 않았다.**

## 폐광의 구멍 신고와 바닥 수정

저장된 기본 외피와 바닥, 실제 Unity MeshCollider, 카메라 충돌을 따로 조사했다. 의도한 입구를 제외한 큰 외피 누출은 이번 검사에서는 검출되지 않았다. 이 결과를 근거로 사용자에게 보인 문제가 없었다고 판단하지 않는다.

| 검사 | 결과 | 범위 |
|---|---|---|
| 저장 메시 Blender BVH | 통과 | 유효 지점 406개·77,952방향, 예상하지 않은 누출 0·반대 법선 명중 0 |
| 실제 Unity Edit 충돌 표면 | 통과 | 398지점·76,416방향, 예상하지 않은 누출 0. 의도한 입구는 허용 |
| 현재 숄더 카메라 충돌·near plane | 통과 | 152지점·5,472 회전/피치 조합에서 벽 통과·near-plane 모서리 통과 0 |
| 기존 폐광 저장 위치의 실제 Play 화면 | 통과, 해당 시점 한정 | 현재 Main Camera의 위치·설정을 복사해 확인. 가까운 벽·천장·바닥이 연속적으로 보였음 |
| 사용자가 보고한 큰 벽·천장 구멍 전체 | 미검증 — 현재 미재현 | 전체 폐광의 실제 입력 이동 및 문제 시점 확보가 필요 |

별도로 **입구 접근 흙이 완성된 실내 바닥과 약 11m 중첩**돼 검은 삼각형이 돌출하는 결함을 확인했다. 내부의 참조 정점 4개가 Y=0.10m를 넘었고 최대 약 0.633m까지 올라가 있었다. 접근 바닥 작성 과정에서 포털 벽의 높이가 바닥에 반영된 흔적이었다.

원본을 보존한 파생 메시에서 중첩 부분을 제거하고 실내 바닥 높이에 접합했다. 첫 수정은 높이 혼합 폭이 실제 격자보다 좁아 30cm 검사 폭에서 최대 높이 변화가 **16.55cm로 실패**했다. 검사 기준은 유지한 채 실제 정점 네 열에 걸쳐 접합을 완화했다. 최종 결과는 **80개 단면·560개 표본 모두 지지, 최대 높이 변화 2.59cm로 통과**했다. 새 렌더 메시와 충돌 메시는 동일한 파생 에셋을 참조하며, 접근 바닥 삼각형 수는 **3,200 → 2,808**이다.

이 값은 접합부 지지와 연속 높이 변화의 결과다. 발 관통이나 보행 완주 측정이 아니다. 오른쪽 입구의 암벽·흙 재질 경계에는 거친 형태가 일부 남아 있다. 작은 퇴화 경계나 비정상 엣지도 발견됐지만, 이를 큰 구멍 신고의 원인으로 단정하지 않았다. 상세 근거와 첫 실패 기록은 `NaturalCave/ShellAudit/DIAGNOSIS.md` 및 해당 검증 원장에 남겼다.

## 효과음

현재 씬은 이미 편집된 PCM 음원과 믹서를 참조하고 있었다. 기존 실제 Unity 합산 출력에서도 최고 약 -11.66 dBFS, full-scale 초과 샘플 0개였으므로, 음원 전체의 디지털 클리핑을 원인으로 단정하지 않았다.

확인한 결함은 **18ms attack·25ms release의 음량 적용이 렌더 Update에 묶여 있던 것**이다. 10–20fps에서는 짧은 페이드가 큰 음량 단차나 갑작스러운 절단으로 변할 수 있었다. UI와 게임 효과음의 페이드를 오디오 샘플 단위 처리로 옮겼다. 메인 스레드는 조용해진 voice를 정리하며, 기존 12개 게임·4개 UI voice 제한, 중복 억제, 갈무리 시작/루프/종료, 음량 옵션은 유지했다.

| 검사 | 상태 | 결과 |
|---|---|---|
| PCM 및 기존 원본 | 통과 | 20개 PCM의 형식·피크·끝점·루프 이음 검사, 원본 45개 해시 보존 |
| production DSP 처리 계약 | 통과 | 8개 검사. 256/1024 frame 버퍼 결과 일치, 메인 Tick 없이 release 종료, 처리 중 GC 할당 0 |
| Unity 연결 | 통과 | 활성 listener 1개, DSP envelope 16개, 48kHz·1024×4 버퍼 및 믹서 연결 |
| 10Hz voice-pool 정리 중 실제 믹서 합산 | 통과 | 9.493초 stereo PCM, 최고 **-11.6629 dBFS**, full-scale 초과 0, mute 교정과 종료 정리 통과 |
| 실제 전투 입력 중 소리·OS/장치 출력·최종 음색 | 미검증 | 위 기록은 Unity listener PCM이며, 스피커·헤드셋 또는 OS 드라이버 청취를 대신하지 않음 |

새 저프레임 진단은 voice-pool 정리 빈도를 10Hz로 제한한 시험이다. 실제 OS 오디오 스레드 중단이나 장치 버퍼 부족을 재현한 시험은 아니다. 상세 보고서는 `Art/PlaytestRecovery/AudioRepair/REPORT.md`에 있다.

## 마당 식생과 원본 보존

새 마당·접근로의 제외 영역만으로는 기존 `EarlyRegionFoliage`의 저장된 Near/Far 행렬을 숨길 수 없었다. 이 컴포넌트가 렌더 시 일반 식생 제외 영역을 다시 조회하지 않기 때문이다. 실제로 마당 안에 남아 있던 소나무·느릅나무 **2개 인스턴스**를 특정해 근거리·원거리 행렬 **6개**를 함께 제거했다. 대상 군락의 남은 침범 뿌리는 0개로 확인됐다.

수정 전 행렬과 화면은 별도로 보관했다. 숲 전체를 재생성하거나 이름만으로 주변 오브젝트를 일괄 비활성화하지 않았다. 두 대상 패킷 이외의 배열과 공급자 소스 참조는 유지했다. 이 국부 정리는 새 마당을 비운 작업이며, 전체 식생 성능이나 모든 원거리 LOD의 합격 판정은 아니다.

현재 작업 전 씬·콘텐츠·식생 제외 데이터는 `VillageOpening/Backups/`에 보관했다. 폐광 바닥의 이전 에셋과 각 수정 단계, 오디오 원본 및 이전 출력 자료도 보존했다. 실제 사용자 저장을 시험용으로 초기화하거나 지우지 않았다.

## 통합 검사와 남은 범위

**실제 Play 연결 API 진단 20개**가 통과했다. 실제 `Session.Interact`, 메뉴 버튼 콜백, `Seat.TryBoard/TryExit`, `SaveNow`를 호출했으며 키보드·마우스 입력을 합성하거나 자동 보행하지 않았다. 시험 중 접근은 명시적인 진단용 순간이동으로 처리했다.

| 항목 | 상태 | 근거와 한계 |
|---|---|---|
| 의뢰 전 호출 잠금·의뢰 수락·보상 0 | 통과 | 실제 UI 콜백 및 Session API |
| 기존 한 대 호출·프로필·전방 방향 유지 | 통과 | 차량 개수·인스턴스 ID·프로필 참조 검사 |
| 이동·운전자 소유·즉시 중복·실제 탑승 중 호출 거절 | 통과 | 실패 전후 위치 보존 확인 |
| 실제 탑승·하차·보행 소유 복원 | 통과 | 기존 Seat API, 실제 입력 시험은 아님 |
| 의뢰·차량 단계 저장과 파일 재읽기 | 통과 | 격리 슬롯 `world-macro-playtest-v2_village-commission-20260915-r1`만 사용 |
| 진단 정리 | 통과 | 차량·플레이어 원위치 복원, 메뉴 종료 |
| 기존 v2/v3 진행·체크포인트·통보·드롭 보존 정책 | 통과 | 메모리 내 정책 시험 20개. 기존 저장에 새 관청 시작을 강제하지 않음 |
| 기록첩·알 수 없는 메뉴 경로 거절 | 통과 | 같은 정책 시험. 기존 상세 내용창 및 나머지 메뉴 경로 유지 |
| 앱 종료·재실행, 사용자의 실제 기존 저장 이행 | 미검증 | 정책 및 격리 파일 재읽기와 구분 |
| 관청→도로→폐광 실제 입력 완주·전투·전체 이동 성능 | 미검증 | 이번에 자동 완주·새 빌드를 만들지 않음 |
| 관청/NPC/첫 화면의 최종 미술·목적 전달력 | 사용자 검토 필요 | 기존 소형 건물 외관 시안과 임시 NPC |
| 금빛 5소켓 3D 오행부·자동차 소환 VFX | 미구현 | 후속 제작 범위 |
| 큰길 밖 강제 주행 제한·자동 운송 | 미구현 | 이번 호출 기능의 규칙으로 추가하지 않음 |

근거 원장은 `Art/PlaytestRecovery/OpeningSequence/village_integration.json`, `Art/PlaytestPolish/Opening/Validation/opening_policy.json`, 이 폴더의 `scene_validation.txt`, `DECISIONS.md`, `Foliage/`와 `NaturalCave/ShellAudit/`다. 이번 작업에서는 새 플레이테스트 빌드·영상·자동 보행 완주를 제작하지 않았다.
