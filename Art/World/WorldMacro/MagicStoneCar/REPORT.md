# 마석 자동차 제작·기술 검수

새 Cabin·Roof·Engine·Wheel을 생성하고, Blender에서 강체 파트와 3단계 LOD를 제작해 Unity TEST 차량에 설치했다. 기존 가마 원본과 자료는 보존했다. 아래의 제작·정적 구성 검사와 실제 Play 진단은 범위를 구분한다. 최종 외관·시야·승차감은 사용자 검토 대상이다.

## 실제 제작 결과

연결된 API에서 `meshy-7`, Standard, PBR, 4K 텍스처, 자동 이미지 변경 OFF로 네 파트를 각각 한 번 요청했다. 네 작업 모두 `SUCCEEDED`, 실제 소비는 **각 30, 합계 120크레딧**이다. 요청 ID와 요청값·원본 다운로드 통계는 [Meshy 원장](Meshy/ledger.json)에 기록했다. 요청 polycount는 최종 내보낸 삼각형 수와 구분한다.

## 모델·재질·연결

- Cabin 전면에 생성된 닫힌 패널과 눈 위치를 가로지르던 면을 국부적으로 제거했다. 창살·기둥·벤치와 원본 UV를 유지하고, 지붕 처마와 전방 엔진 위치를 맞췄다.
- 각 파트 3LOD와 Support 3LOD, 합계 15개 FBX를 빈 Blender 장면에 다시 가져왔다. 삼각형 수·UV 존재·유한 좌표·방향·크기 검사 **통과**. 자세한 수치와 해시는 [Blender 전달 기록](Blender/DELIVERY.json) 및 [조립 기록](Blender/Assembly.json)에 있다. 이 검사는 모든 UV 왜곡·노멀 방향·Unity 화면 품질의 전수 검사가 아니다.
- 중앙 청록 렌즈의 원본 면을 `MagicStoneCore`로 분리했다. 단독·영역 이미지로 렌즈 위치를 확인했으며, LOD0 35 tris다. 소켓과 실제 경계 중심 차이는 약 0.014mm다. 미검증 `EmissionCandidateMask`는 발광에 사용하지 않는다.
- BaseColor·Normal 실물은 파트별 4096², 원본 packed MR은 2048²다. MR의 B 금속/G 거칠기를 Unity R 금속/A 매끄러움으로 변환했다. 원본 AO가 없어 중립 흰색을 제공했다. 4K 요청이 모든 결과 맵의 4K를 보장한 것으로 보고하지 않는다.
- 매크로 씬의 환경광·반사 강도가 0인 조건에서 차량 표면이 지나치게 어두워져, 차량 소유 재질 7개에 `Oheangbu/MagicStoneCarSurface`를 적용했다. URP `UniversalFragmentPBR`의 간접 확산광 입력에 **국부 하한 0.40**, 텍스처 채도 **0.70**, 매끄러움 맵 배율 **0.85**를 사용한다. 금속·거칠기·노멀 맵은 유지한다. 일반 목재·금속의 보정은 emission에 더하지 않으며, emission은 분리한 마석과 등롱 면으로 제한한다. [surface_look.json](surface_look.json)은 적용 시점 기록이고, 그 안의 `visualReview=PENDING` 이후에 아래 최신 정지 이미지 5종을 촬영했다. 이미지의 셰이더 패스 준비 기록과 사용자 최종 비주얼 승인은 구분한다.
- 이 국부 재질 변경은 전역 환경광·반사·기존 월드 표면, Meshy 원본 메시·텍스처, 기존 가마, 차량 물리값을 바꾸지 않았다. [최신 설치 감사](setup_audit.json)에 차량 전용 PBR 연결·국부 간접광·발광 범위 검사 결과를 기록했다.
- 바퀴는 반지름 0.6m, 축 X, 기존 물리 장착점과 구동 설정을 유지한다. 전방 엔진 돌출부를 감싸는 BoxCollider 추가는 [engine_collider.json](engine_collider.json)에 별도 기록했다. 정적 설정 보존만으로 새 충돌 형상의 주행 반응을 통과 처리하지 않는다.
- 새 차량은 TEST 표현·조작 범위다. 자동 이동망·빠른 이동 규칙이나 전투 기능을 추가하지 않았다. 지속 발광은 승인된 마석·등롱 범위로 한정한다.

카메라의 최신 한정 Play API 검사는 **14개 항목을 실제 실행**했다. 보행 OnEnable의 발 위치 보존, 승하차 두 차례, 차량 시점 전환, 운전석 기본 피치 12° 유지, 하차 후 카메라 소유권 복귀, 보행·차량 카메라에 임시 콜라이더를 둔 SphereCast 수축을 포함한다. 운전석 피치는 작성값 12°와 중립 입력의 관측값 12°가 일치했으며, 허용된 차체 흔들림과 소켓 자체의 기본 기울기를 구분했다. 보행 카메라 거리는 2.755→1.383m, 차량 카메라는 6.053→3.192m로 줄었다. 검사 후 임시 콜라이더를 제거했다. 실제 E/V 키 입력을 합성한 검사는 아니며, 임의의 월드 벽·모서리·경사에서 모두 안전하다고 주장하지 않는다.

**미검증:** 실제 키 입력, 전체 경로 보행·장거리 주행, 일반 지형에서의 충돌·전복·승차감, 30·60·120fps 고정 조건, 목표 120fps 달성, 최종 외관과 거리별 LOD 전환의 사용자 승인. 구동·물리 진단의 합격은 위에 기록한 설치 위치의 짧은 API 시험 범위에 한정한다.

환경 성능은 [최종 동일 구도 비교 요약](../Dressing/FINAL_STATUS.md)과 [원본 수치·비교 기준](../Dressing/performance_summary.json)으로 분리했다. 이는 정지한 한 지점의 환경 측정이며, 주행 중 차량 성능이나 전체 맵 120fps 검증을 뜻하지 않는다.

## 이미지와 전달 파일

[검토 페이지](REVIEW.html)에 새 차량 재질을 적용한 **1920×1080 정지 이미지 5종**을 제공한다: [외관](exterior.png), [운전석](seated.png), [보행 숄더뷰](player.png), [차량 숄더뷰](vehicle_shoulder.png), [구동부](engine.png). 각각의 JSON에 촬영 시점·Play·탑승 상태와 셰이더 패스 준비 결과를 기록했다. 정적 카메라를 소켓에 놓은 그림을 실제 탑승 입력 검증으로 보고하지 않는다. 최종 비주얼 판단은 사용자에게 맡기며 영상은 제작하지 않았다.

**출발 효과 진단 이미지 추가 확보:** [ignition.png](ignition.png), [ignition.json](ignition.json). 최신 기록은 `CAPTURED_DIAGNOSTIC`이며 1920×1080 한 장을 실제 모터 토크로 시작된 `PATTERN` 구간에서 촬영했다. 임시 물리 정지벽을 둔 API 진단으로, 활성화 1회·문양 시작 1회, 활성화 후 약 0.311초, 최대 위치 변화 0.019m다. 일반 자유 주행·실제 키 입력·최종 비주얼 승인과 구분한다. 촬영 뒤 임시 충돌체·입자 제거와 차량·운전자·좌석 소유권 복원을 기록했다. 따라서 현재 전달 이미지는 정적 구도 5종과 출발 진단 1종, 합계 6종이다.

- 편집 원본: `Blender/MagicStoneCar_{Part}_LOD{0,1,2}.blend`, `Blender/MagicStoneCar_Assembly_LOD{0,1,2}.blend`. 텍스처를 포함했다.
- 제작 단계 보고서: [Blender/REPORT.md](Blender/REPORT.md). 마지막 국부 수정 뒤 일부 Blender 운전석 비교 이미지를 메모리 한도로 재촬영하지 못한 사실을 기록했다. 최신 Unity 캡처와 혼동하지 않는다.
- Unity 소유 폴더: `Oheangbu/Assets/_Project/Art/World/WorldMacro/MagicStoneCar/`의 `Models/`, `Textures/`, `Prefabs/MagicStoneCar_TEST.prefab`, `TextureManifest.json`, `SocketManifest.json`.
- 원본: `References/`, `Concepts/`, `Meshy/`. 기존 `Palanquin/` 제작본과 분리했다.

한 번에 Blender 한 프로세스만 사용했으며 시스템 커밋 85% 기준에서 추가 작업을 중단한 이력은 [Blender/memory_guard_event.json](Blender/memory_guard_event.json)에 남겼다. Unity에서 차량 정지 이미지 5종을 저장한 뒤 첫 출발 효과 촬영은 메모리 한도로 중단하고, 씬 저장 후 Unity를 일시 종료해 메모리를 회수했다. 이후 재시도에서 출발 진단 이미지를 확보했으며, 최종 촬영 시 커밋은 렌더 직전 약 72.92%·촬영 후 73.18%였다. 물 표현 작업은 보류하고, 보행 완주와 실제 크기 캡슐의 시야·승차감 검토는 사용자에게 맡긴다. 캡슐 기준은 높이 1.75m·지름 0.56m·눈높이 1.62m다.
